## 1. 핵심 공간 배치 파라미터 (YAML 기하 치수)

[s2e_auto_mdp.py](file:///C:/Users/USER/Desktop/캡스톤/캡2-논문/go2_ws/scratch/s2e-urban-rl/urbansim/primitives/navigation/s2e_auto_mdp.py#L893-L902)의 수식에 매핑되어 장애물 스폰 위치를 제한하는 핵심 6대 파라미터입니다:

```
  ◀─────────────────────── 인도 폭 (Sidewalk Width) ───────────────────────▶
  ┌────────────────────────────────────────────────────────────────────────┐ ▲
  │                                                                        │ │ boundary_clearance
  │   [장애물 에셋] (반경: radius)                                         │ ▼
  │   ───┬───                                                              │ 
  │      │                                                                 │ 
  │      │ ◀─── [중앙 주행 통로] (최소 폭: minimum_passage_width) ───▶     │ 
  │      │                                                                 │ 
  │   ───┴───                                                              │ ▲
  │   [장애물 에셋] (반경: radius)                                         │ │ boundary_clearance
  │                                                                        │ ▼
  └────────────────────────────────────────────────────────────────────────┘
```

1. **`minimum_passage_width` (기본값: `0.8` m)**
   * **기능**: 인도 중앙에 남겨둘 최소한의 보행 통로 폭입니다.
   * **수식**: `inner_limit = 0.5 * minimum_passage_width + radius_obstacle`
   * **효과**: 이 값을 설정하면 장애물이 좌우로 아무리 밀집되어 배치되어도, 로봇개가 지나갈 수 있는 최소 폭은 항상 기하학적으로 통제되어 막다른 길(Dead-end)이 생성되는 것을 방지합니다.

2. **`object_min_spacing` (기본값: `1.35` m)**
   * **기능**: 장애물 상호 간의 최소 직선 분리 거리입니다.
   * **효과**: 여러 개의 장애물이 뭉쳐서 하나의 거대한 통과 불가능한 벽을 이루는 현상을 방지하여, 장애물 사이로 지그재그 회피할 수 있는 공간을 보장합니다.

3. **`object_boundary_clearance` (기본값: `0.10` m)**
   * **기능**: 인도의 측면 경계턱(Curb) 또는 벽면으로부터 장애물 외곽선까지의 최소 마진입니다.
   * **효과**: 장애물이 인도 바깥으로 탈선하여 차도에 걸치거나 어색하게 허공에 뜨는 렌더링 문제를 방지합니다.

4. **`endpoint_object_clearance` (기본값: `2.5` m)**
   * **기능**: 로봇개의 시작 지점(Start)과 최종 골인 지점(Goal) 반경 내 장애물 배치 금지 구간입니다.
   * **효과**: 학습 리셋 직후 로봇개가 장애물에 끼여 즉시 낙하하거나 골인 지점 바로 앞에 바위가 배치되어 터미네이션되는 억까 상황을 방지합니다.

5. **`object_longitudinal_jitter` (기본값: `0.20` m)**
   * **기능**: 진행 방향(종방향)으로의 스폰 위치 흔들기 범위입니다.
   * **효과**: 장애물 배치가 일정한 간격으로 고착화되는 오버피팅을 방지하기 위해 랜덤 오프셋을 더해 학습 난이도를 높입니다.

6. **`object_max_footprint` (기본값: `0.75` m)**
   * **기능**: 배치 후보로 오를 수 있는 가상 장애물 메시의 최대 반경입니다.
   * **효과**: 너무 큰 장애물 에셋(예: 차량, 대형 벤치 등)이 들어와 맵 전체를 막아 버리는 현상을 사전에 커트합니다.

## 2. 장애물 배치 시나리오 유형 (Top-Down 평면 시각화)

S2E V2에서는 맵 난이도 설정을 위해 6가지 정밀 시나리오 모드를 제공합니다.

### ① `clean` (장애물 없음)
* **스폰 구조**: 장애물 개수가 0개이거나 주행을 방해하지 않는 구석에만 희소 배치됩니다.
* **평면도**:
  ```
  [Start] ── ── ── ── ── ── ── ── ── ── ── ── ── ── ── ── ── [Goal] (Clean)
  ```

### ② `sparse` (저밀도 랜덤 회피)
* **스폰 구조**: 보도 전역에 2~5개 내외의 장애물이 드문드문 불규칙하게 흩어집니다.
* **평면도**:
  ```
  [Start] ── ── ── ── (Obstacle) ── ── ── (Obstacle) ── ── ── [Goal]
  ```

### ③ `dense` (고밀도 복합 정체)
* **스폰 구조**: 12~24개의 장애물이 가득 들어차 보행로 전체의 틈새 난이도가 급상승합니다.
* **평면도**:
  ```
  [Start] ─(Ob)─(Ob)─ ─(Ob)─(Ob)─ ─(Ob)─(Ob)─ ─(Ob)─(Ob)─ [Goal]
  ```

### ④ `bottleneck` (중앙 협소 병목 생성)
* **스폰 구조**: 장애물이 인도 경계부 좌우 측에 대칭 쌍을 이루어 좁은 깔대기 통로를 형성합니다.
* **평면도**:
  ```
          ┌───────┐                       ┌───────┐
          │ (Ob)  │                       │ (Ob)  │
  [Start] └───────┘  ◀─── [병목 통로] ───▶ └───────┘  ─── [Goal]
          ┌───────┐                       ┌───────┐
          │ (Ob)  │                       │ (Ob)  │
          └───────┘                       └───────┘
  ```

### ⑤ `slalom` (지그재그 슬라롬 구동)
* **스폰 구조**: 장애물이 좌 ➔ 우 ➔ 좌 ➔ 우 순서로 교대로 스폰되어 로봇개가 요동치며 조향 선회할 수밖에 없게 만듭니다.
* **평면도**:
  ```
          ┌───────┐                               
          │ (Ob)  │ (좌측 편향)                   
  [Start] └───────┘         ┌───────┐             ─── [Goal]
                            │ (Ob)  │ (우측 편향)  
                            └───────┘             
  ```

### ⑥ `curve_clutter` (회전구간 집중 정체)
* **스폰 구조**: 곡률 계산 수식(`path_curvature_profile`)을 통해 인도 중 **급격하게 굽어지는 회전 코너부**를 탐색해 그 반경에만 장애물을 몰아서 스폰합니다.
* **평면도**:
  ```
  (직선 구간 - 깨끗함)         (곡선 회전 구간 - 장애물 밀집)
  [Start] ── ── ── ── ── ── ── ┐ (Ob) (Ob)
                               │ (Ob)
                               ▼ [Goal]
  ```

## 3. 커리큘럼 연동 및 시나리오 믹싱 방법

각 커리큘럼 YAML 파일의 `generator_config` ➔ `obstacle_scenarios` 구조를 통해 위 시나리오들의 스폰 가중치 확률(Probabilities)과 타겟 스폰 개수 범위를 동적으로 할당할 수 있습니다.

### 📝 설정 조율 템플릿
```yaml
Env:
  generator_config:
    obstacle_scenarios:
      probabilities:
        clean: 0.10          # 10% 확률로 장애물 없는 클린 맵 생성
        sparse: 0.20         # 20% 확률로 흩어진 장애물 생성
        dense: 0.20          # 20% 확률로 고밀도 생성
        bottleneck: 0.20     # 20% 확률로 병목 구간 생성
        slalom: 0.20         # 20% 확률로 지그재그 생성
        curve_clutter: 0.10  # 10% 확률로 코너 집중 적재 생성
      active_count_ranges:
        clean: [0, 1]        # clean 모드일 때 스폰할 개수 범위
        sparse: [2, 5]       # sparse 모드일 때 스폰할 개수 범위
        dense: [12, 24]      # dense 모드일 때 스폰할 개수 범위
        bottleneck: [4, 8]   # bottleneck 모드일 때 스폰할 개수 범위
        slalom: [6, 12]      # slalom 모드일 때 스폰할 개수 범위
        curve_clutter: [6, 12] # curve_clutter 모드일 때 스폰할 개수 범위
```

## 4. Sim-to-Real 대비 장애물 튜닝 가이드라인

학습 진행 상황 및 실물 로봇 동작 상태에 맞춰 다음과 같이 파라미터를 교정하는 것을 권장합니다:

*   **증상: 로봇개가 좁은 장애물 틈새 사이에서 주춤거리고 꼼짝 못 할 때**
    *   *원인*: 학습 단계의 최소 통로 폭 제약이 로봇의 최소 회전 회피 반경보다 좁기 때문입니다.
    *   *처방*: `minimum_passage_width`를 **`0.8` ➔ `0.9` 또는 `1.0`**으로 넓혀 학습 통로 여유를 보장해 보십시오.
*   **증상: 곡선 구간에서 코너를 들이받거나 길 밖으로 추락할 때**
    *   *원인*: 굴곡진 구간의 장애물 스캔 및 감속 회피 시점이 너무 늦습니다.
    *   *처방*: 코너에 위치한 장애물 빈도를 낮추도록 `curve_clutter` 확률을 줄이거나, `endpoint_object_clearance`를 넓혀 회전 직후 주행 안정 거리를 확보해 주십시오.
*   **증상: 장애물 사이를 지날 때 보행 안정성이 크게 흔들리고 넘어질 때**
    *   *원인*: 장애물 간의 간격이 너무 촘촘하여 급격하게 조향하다가 관성에 의해 넘어집니다.
    *   *처방*: `object_min_spacing`을 **`1.35` ➔ `1.6`**으로 늘려주어 감속 및 자세 제어가 개입할 물리적 시간과 이동 거리를 벌어다 주십시오.
