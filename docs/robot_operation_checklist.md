# 📋 Unitree Go2 SLAM & 자율주행 최종 구동 체크리스트

본 문서는 **로봇 전원 ON 상태부터 SLAM 맵핑, 그리고 Windows 노트북 모니터링 및 자율주행(Nav2) 기동까지** 거쳐야 하는 모든 물리적/소프트웨어적 점검 단계와 이슈 대처법을 집대성한 단일 통합 체크리스트입니다.

---

## 1단계: 하드웨어 및 케이블 물리 점검
로봇을 켜기 전에 반드시 눈으로 확인해야 하는 센서 물리 연결 상태입니다.

- [ ] **D435i 카메라 연결 포트 확인**: 
  * Jetson 보드의 **USB 3.0 포트(파란색 포트)**에 견고하게 연결되어 있는지 확인합니다. USB 2.0 포트에 연결되면 대역폭 부족으로 RGB 카메라 스트림이 0 Hz로 차단됩니다.
- [ ] **LAN 케이블 연결 상태 확인**:
  * Jetson 보드의 기본 유선 포트(`eth0`)에 로봇 본체와 연결된 LAN선 및 외부 네트워크망(학교 유선랜) 케이블이 정상 체결되어 있는지 확인합니다.
- [ ] **로봇 본체 상태**: 
  * 로봇 배터리가 충분한지 확인하고, 로봇 주변에 부딪힐 장애물이 없는 안전한 공간에 기립(Stand)시킵니다.

## 2단계: 네트워크 및 DDS 설정 (통신 확인)
로봇(Jetson)과 외부 개발용 노트북이 동일한 ROS 2 네트워크 도메인에서 정상 통신하도록 셋업하는 과정입니다.

- [ ] **Jetson 네트워크 멀티 IP 설정**:
  * 로봇 온보드 PC(Jetson)에 접속하여 인터넷(개발용)과 로봇 본체 제어망을 동시 가동하는 스크립트를 실행합니다.
  ```bash
  cd /home/unitree/go2_ws
  ./set_both.sh
  ```
  * *출력 확인*: `eth0` 카드에 외부 IP(`203.252.107.219`)와 로봇망 보조 IP(`192.168.123.99`)가 나란히 떠 있는지 콘솔 화면을 확인합니다.
- [ ] **유니캐스트 피어(`Peers`) 설정 확인**:
  * 학교 유선랜/공유기는 멀티캐스트를 차단하므로, 노트북과 Jetson이 1:1로 직접 패킷을 던질 수 있도록 `cyclonedds.xml`을 사전에 맞춰둡니다.
  * **노트북의 `cyclonedds.xml`** 파일 내 `<Peers>` 영역에 **노트북 IP**와 **Jetson IP(`203.252.107.219`)**가 정확히 등록되어 있는지 확인합니다.
- [ ] **네트워크 핑(Ping) 테스트**:
  * **노트북 터미널**: `ping 203.252.107.219` (Jetson으로 핑이 가는지 확인)
  * **Jetson 터미널**: `ping 192.168.123.161` (로봇 본체 보드로 핑이 가는지 확인)

## 3단계: 카메라 및 센서 하드웨어 가동 확인
Jetson 내부에서 RealSense D435i 카메라가 정상적으로 인식되고 IMU 데이터가 커널 상에 올라오는지 점검합니다.

- [ ] **USB 자동 절전(Autosuspend) 기능 비활성화 확인**:
  * USB 포트가 전원 절약 모드로 들어가 카메라가 끊기는 현상을 차단합니다.
  ```bash
  cat /sys/bus/usb/devices/2-2/power/control      # 출력 결과: on
  cat /sys/bus/usb/devices/2-2/power/autosuspend  # 출력 결과: -1
  ```
- [ ] **USB HID 드라이버 바인딩 확인**:
  * D435i의 자이로/가속도 센서(HID)가 제대로 드라이버에 잡혔는지 체크합니다.
  ```bash
  ls -la /sys/bus/usb/devices/2-2:1.5/driver
  # 출력 경로 끝에 'usbhid'가 나타나면 성공
  ```
- [ ] **RealSense 기기 및 IMU 스트림 탐지**:
  * 카메라 펌웨어 버전과 내부 IMU 장치가 정상 검출되는지 확인합니다.
  ```bash
  /usr/local/bin/rs-enumerate-devices | grep -E "Name|Firmware|IMU"
  # D435i 이름과 IMU(Accel/Gyro) 관련 정보가 제대로 출력되는지 검증
  ```

## 4단계: 실내/실외 맵핑(SLAM) 및 자율주행 실행
상황에 맞게 스크립트를 골라서 구동하며, 터미널 탭별 실행 상태를 모니터링합니다.

### 🏠 옵션 A: 실내 (VIO + Leg + IMU 3원 융합 셋업)
* **특징**: 태양광이 없는 실내에서 리얼센서 카메라 오도메트리를 기반으로 다리 정보와 IMU를 합쳐 정밀 맵핑합니다.

- [ ] **실내 맵핑 실행**:
  ```bash
  ./run_map_indoor.sh
  ```
  * *대기*: 리얼센서 하드웨어 안정화를 위해 **25초**간 슬립이 걸립니다. 대기 후 터미널 탭들이 모두 정상 가동되는지 확인합니다.
- [ ] **실내 자율주행(Nav2) 실행 (기존 맵이 있는 경우)**:
  ```bash
  ./run_localization_indoor.sh
  ```

### 🌲 옵션 B: 실외 (LiDAR-Inertial 셋업)
* **특징**: 햇빛이 강한 야외에서는 리얼센서 비주얼 오도메트리를 차단(`visual_odometry:=false`)하고, 로봇 본체의 4D LiDAR L1 및 온보드 IMU 오도메트리를 사용하여 맵핑합니다.

- [ ] **실외 맵핑 실행**:
  ```bash
  ./run_map_outdoor.sh
  ```
- [ ] **실외 자율주행(Nav2) 실행 (기존 맵이 있는 경우)**:
  ```bash
  ./run_localization_outdoor.sh
  ```

## 5단계: 실시간 데이터 검증 및 모니터링 (노트북)
구동 스크립트가 뜬 뒤, 센서 토픽들이 유실 없이 지정 주기에 맞추어 발행되고 있는지 검사합니다.

- [ ] **ROS 2 토픽 수신 확인 (노트북/Jetson 새 터미널)**:
  ```bash
  ros2 topic list
  # /camera/color/image_raw, /camera/imu, /imu/data, /odom 등의 토픽이 정상 조회되는지 확인
  ```
- [ ] **주파수(Hz) 검증**:
  - [ ] `/camera/imu` ➔ **약 200 Hz** (리얼센서 원본 IMU)
  - [ ] `/imu/data` ➔ **약 200 Hz** (Madgwick 필터링된 IMU)
  - [ ] `/camera/color/image_raw` ➔ **약 15 ~ 30 Hz**
  - [ ] `/camera/aligned_depth_to_color/image_raw` ➔ **약 15 ~ 30 Hz**
- [ ] **노트북(Windows) Foxglove Studio 연결**:
  * 노트북에서 Foxglove Studio를 실행합니다.
  * Connection 항목에서 `Foxglove WebSocket`을 선택하고 주소창에 `ws://203.252.107.219:8765`를 입력해 연결합니다.
  * *확인*: 카메라 이미지 패널, TF 트리 구조, 라이다 3D 포인트 클라우드, 지도(Occupancy Grid)가 실시간으로 노트북 화면에 그려지는지 모니터링합니다.

## 🚨 트러블슈팅 가이드 (장애 상황 즉시 대응)

* **Q1. 카메라 노드는 떴는데 `/camera/imu` 토픽 주파수가 0 Hz(데이터 안 옴)인 경우**
  * **원인**: Jetson이 전용 RSUSB 라이브러리(`/usr/local/lib/librealsense2.so`) 대신 시스템 기본 라이브러리를 로드하여 HID 가속도/자이로 센서를 열지 못했기 때문입니다.
  * **대처**: 실행 스크립트 실행 시 카메라 구동 명령어 앞에 `export LD_PRELOAD=/usr/local/lib/librealsense2.so;` 환경 변수가 정상 반영되었는지 스크립트 소스를 다시 점검합니다.
* **Q2. 카메라 노드가 켜지자마자 `Failed to set power state` 에러를 내며 크래시가 발생하는 경우**
  * **원인**: USB 자동 절전(Autosuspend) 기능이 활성화되어 카메라 리셋 신호 도중 USB 포트 전원이 완전히 내려갔기 때문입니다.
  * **대처**: `99-realsense-libusb.rules` udev 규칙을 새로고침하거나, 본 체크리스트 **3단계** 명령어로 수동 전원 차단 비활성화를 실행합니다.
* **Q3. 로봇과 노트북이 같은 망에 연결되어 있고 ping도 가는데 토픽이 노트북에서 조회되지 않는 경우**
  * **원인**: 학교 네트워크가 멀티캐스트 패킷을 드롭하여 상호 검색이 되지 않는 상황입니다.
  * **대처**: 노트북과 Jetson 양측 환경에서 `cyclonedds.xml` 파일 내 `<Peers>`에 서로의 IP가 똑바로 매핑되었는지 및 `$CYCLONEDDS_URI` 환경 변수가 지정 경로를 완벽히 가리키고 있는지 재검증합니다.
