**먼저 필요한 용어**

| 용어 | 의미 |
|---|---|
| VLM | 카메라 영상을 보고 다음에 어느 지점으로 갈지 판단하는 영상·언어 모델 |
| PixelNav | 목표가 표시된 영상과 이후 영상을 보고 전진·좌회전·우회전·정지·위보기·아래보기 중 하나를 출력하는 모델 |
| 위치 추정값, 오도메트리 | 로봇 센서로 추정한 위치와 방향. 이동하면서 오차가 누적될 수 있음 |
| 주변 관측 | 로봇을 여러 방향으로 돌려 영상을 얻고 다음 이동을 판단하는 과정 |
| 동작 완료 응답 | 실행기가 실제 전진·회전 처리를 마친 뒤 상위 프로그램에 알리는 결과 |
| 목표 표시 | PixelNav에 목적지를 알려주기 위해 영상의 특정 위치를 표시한 입력 |

**현재 시스템의 전체 흐름**

| 순서 | 현재 동작 | 담당 |
|---|---|---|
| 1 | 표시된 시작 위치·방향에 로봇을 놓고, 저장한 목표 번호 선택 | 사람·실행 도구 |
| 2 | 시작 시 위치 추정값을 읽고 저장된 목표를 현재 위치 좌표계에 연결 | 로봇용 좌표 변환 |
| 3 | 영상·위치·카메라 정보를 같은 관측으로 묶어 전달 | 로봇용 입력 처리 |
| 4 | 영상을 보고 다음 중간 목표 결정 | VLM |
| 5 | 중간 목표로 가기 위한 전진·회전·정지 등의 행동 결정 | PixelNav |
| 6 | 행동을 Go2 속도 명령으로 실행하고 이동량·정지 상태 확인 | 로봇용 실행기 |
| 7 | 이동 중 다음 목표 계산. 방향 변경·재관측 필요 시 현재 한 동작 완료 후 전환 | 기존 비동기 계획 + 실로봇 전환 처리 |
| 8 | 추정 목표 거리 1m 이내 진입 시 도착 종료. 마지막 바라보는 방향은 별도 정렬하지 않음 | 도착 판정 |

**1. 추가한 기능 — 현재 사용 중인 실로봇 전용 처리**

| 추가한 것 | 필요한 이유 | 구체적으로 만든 기능 |
|---|---|---|
| ① 시작점·목표 좌표 연결 | 로봇을 켜거나 실험을 다시 시작하면 위치 추정 좌표가 달라질 수 있음 | 표시된 같은 시작 위치·방향에서 현재 위치 추정값 저장 → 저장된 상대 목표를 현재 좌표에 연결 → 로봇이 움직일 때마다 목표까지 거리·방향 계산. 시작 방향 차이도 계산에 반영 |
| ② 실제 로봇 구동 연결 | 시뮬레이터에 보내던 전진·회전 행동을 Go2 명령으로 실행해야 함 | 정책 행동을 전진 속도·회전 속도로 바꿔 Unitree 구동 API에 전달. 일반 전진 한 번은 25cm, 정책 좌우 회전 한 번은 30°. 실제 실행 결과를 상위 정책에 반환 |
| ③ 위보기·아래보기의 실행 규칙 | 고정 카메라에는 독립적으로 위·아래를 향하게 하는 장치가 없음 | 정책이 위보기 또는 아래보기를 출력하면 실제 20cm 전진으로 실행. 원래 정책 출력과 실제 전진을 따로 기록. 이동 완료와 후속 새 영상 확인 후 다음 판단. 모델의 정지 출력은 유지 |
| ④ 정책용 4:3 카메라 입력 | 실제 카메라 영상과 정책에 맞춘 영상 크기·시야가 다름 | 카메라 보정값으로 각 영상 위치가 바라보는 방향 계산 → 촬영된 범위 안에서 640×480 정책 영상 구성 → 목표 표시도 같은 변환 적용 → 정책이 예측한 영상 좌표를 원래 카메라 좌표로 환산 |
| ⑤ 로봇·Jetson 시각 차이 보정 | 센서에 기록된 시각과 컴퓨터 시각이 달라 자료의 오래됨을 잘못 판단할 수 있음 | 초기 1초 이상 자료에서 공통 시각 차이를 추정하고 실행 중 고정. 중복·역순 자료가 최신 상태를 갱신하지 못하게 하고 시계 급변을 검출 |
| ⑥ 명령 갱신 중단 시 정지 | 상위 프로그램이 멈춰도 마지막 이동 요청이 계속 유지되는 상황에 대비해야 함 | 별도 감시 실행 흐름에서 마지막 요청 시각 확인. 약 0.3초 동안 이동 명령 갱신이 없으면 정지 요청. 취소됐거나 유효시간이 지난 명령을 거부 |
| ⑦ 실행환경 간 연결 | 내비게이션, PixelNav 추론, Go2 구동 코드의 소프트웨어 환경이 다름 | ROS Jazzy 내비게이션, 별도 Python/Torch 정책 추론, ROS Foxy 구동 프로그램을 분리해 실행하고 같은 컴퓨터 안의 통신 통로로 연결. VLM은 원격 서버에 요청 |
| ⑧ 실험 기록·반복 실행 | 어떤 영상·판단·명령에서 실패했는지 다시 확인하고 방법 간 비교해야 함 | 회차별 목표, 영상, 정책 출력, 실행 명령·결과, 위치 궤적, 소요시간, 종료 이유 저장. 새 시도는 새 회차로 보관. 사람 개입·접촉·진로 방해도 별도 기록 |

**2. 수정한 기능 — 현재 동작을 바꾼 구체적 내용**

| 수정한 것 | 해결하려던 문제 | 현재 구현의 처리 |
|---|---|---|
| ① 전진·회전 완료 판정 | 명령을 일정 시간 보냈다는 사실만으로 요청 거리·각도 도달을 보장할 수 없음 | 위치 추정값에서 실제 이동 거리·회전각 계산. 목표 허용 범위와 정지 상태를 새 센서 자료로 확인한 뒤 완료 처리. 자료가 오래되거나 움직임이 없으면 실패 이유 반환 |
| ② 전진 중 방향 유지 | 실제 보행이 원하는 방향에서 벗어날 수 있음 | 전진 명령과 함께 현재 방향 오차를 줄이는 작은 회전 명령 전송. 가속·감속 제한 적용. 큰 좌우 회전 행동은 별도로 실행 |
| ③ 짧은 전진의 멈춤·재출발 | 완료 경계 부근에서 멈춘 뒤 몸체가 되밀리면 완료와 재전진이 반복될 수 있음 | 감속 목표를 허용 범위의 안쪽으로 조정. 정지 시작 후 새 위치 자료 두 개로 안정 확인 전까지 재보행 억제. 안정 후 거리 조건을 만족하면 완료, 부족하면 추가 보정 |
| ④ 회전 후 정지·보정 | 목표 방향을 지나치거나, 멈춘 뒤 몸체가 되돌아올 수 있음 | 목표 부근에서 정지 명령 유지. 실제 각도·회전속도·짧은 시간 동안의 각도 변화를 확인하고 완료 또는 잔여각 보정. 현재 회전 명령 설정은 0.8rad/s |
| ⑤ 주변 관측 후 방향 복귀 | 회전 명령 사이에도 몸체 방향이 바뀌어 명령 각도 합만으로는 정확히 복귀하기 어려움 | 관측 시작 시 실제 방향 저장. 다음 회전마다 현재 방향과 비교해 필요한 각도 계산. 각 영상에 실제 관측 방향 기록. 마지막 복귀도 새 위치·방향 자료로 확인 |
| ⑥ 영상과 위치의 시각 연결 | 과거 영상에 현재 위치를 붙이거나, 위치 자료가 늦어 영상과 짝을 계속 못 찾는 문제 | 영상 시각 앞뒤의 위치로 당시 위치 추정. 보관한 영상 중 위치 계산이 가능한 가장 최신 영상 선택. 동작 후 위치가 준비된 뒤 실행 결과 반환 |
| ⑦ 영상 색상·왜곡·크기 정보 | 영상 색상 순서가 다르고 크기·왜곡 처리 후 카메라 정보가 어긋날 수 있음 | 색상 순서를 BGR에서 RGB로 변환. 왜곡 여부에 맞춰 영상 처리. 1280×720 원본을 640×360으로 줄일 때 초점거리·영상 중심 좌표도 함께 축소. 그 뒤 정책용 4:3 변환 적용 |
| ⑧ 자세 센서 숫자 순서 | Go2가 제공하는 자세 숫자 네 개의 저장 순서가 ROS의 기대 순서와 다름 | 네 숫자를 ROS 규격 순서로 재배열한 뒤 로봇 자세로 해석 |
| ⑨ VLM 후보의 좌우 방향 | 로봇 좌표의 ‘왼쪽 양수’와 후보 설명의 ‘오른쪽 양수’를 연결할 때 부호 변환 누락 | VLM에 전달하는 후보 방향의 부호를 수정. 왼쪽·오른쪽 후보가 최종 목표에서 얼마나 벗어났는지 올바른 방향으로 계산 |
| ⑩ 방향 변경 판단 뒤 기존 전진 지속 | VLM이 다른 방향을 보라고 판단해도 PixelNav의 여러 행동이 끝날 때까지 계속 전진할 수 있음 | 지금 실행 중인 전진·회전 한 번이 완료되면 기존 행동 묶음 종료. 정지 확인 후 주변 관측과 새 판단으로 전환 |
| ⑪ 정상 관측 정지와 실제 실패 구분 | 주변을 보려고 멈춘 동작을 ‘막힘·진행 없음’으로 오해하거나 실제 센서 오류가 가려짐 | 의도적인 관측 전환은 정상 중간 종료로 기록. 실제 이동 실패·센서 오류는 원래 실패 이유 유지. 정상 전환을 최종 목표 도착으로 표시하지 않음 |
| ⑫ 첫 행동 전 관측 요청 | 새 목표를 받았지만 아직 실행한 행동이 없을 때 관측 정지가 오면, 이전 행동 결과를 찾다가 오류·대기 발생 | 행동이 0회여도 새 관측 조건을 확인해 정상 전환 결과 반환. 실행하지 않은 행동의 결과를 요구하지 않음 |
| ⑬ 늦게 도착한 목표·응답 | 취소된 목표가 다시 실행되거나 이전 행동 결과가 새 목표에 섞일 수 있음 | 목표·실행 식별자로 이전 결과 구분. 이전 작업을 끝낸 뒤 완료 응답. 취소된 이동 후보 폐기. 새 목표에서 이전 명령 재사용 차단 |
| ⑭ 실패 정보의 실제 VLM 전달 | 로봇 이동 실패가 내부 기록에만 남으면 다음 판단이 실패를 모른 채 반복될 수 있음 | 진행 없음·명령 실패·결과 대기 초과 등을 다음 VLM 요청에 전달. 이미 처리한 과거 실패가 늦게 다시 반영되지 않도록 시각 확인 |
| ⑮ 카메라 바로 아래의 가까운 목표 | 가까운 목표까지 거리만 기준으로 후보를 만들면 후보가 모두 화면 아래로 사라질 수 있음 | 가까운 구간에서 현재 카메라가 실제로 볼 수 있는 바닥 후보 사용. 최종 목적지 자체는 유지하고 후보를 영상으로 검증 |
| ⑯ 후보 선별에 목표 정보 반영 | 처음 몇 후보를 고를 때 목표 방향·거리가 충분히 반영되지 않을 수 있음 | 후보 방향·이동거리로 계산한 목표까지 예상 잔여 거리와 우선순위를 후보 선별·최종 판단에 함께 전달. 탈출·후퇴 등의 별도 모드에는 같은 순위 강제하지 않음 |
| ⑰ 미검사 후보가 남은 경우 처리 | 먼저 고른 세 후보가 영상 검사에서 탈락하면 다른 후보도 없는 것으로 처리할 수 있음 | 해당 경우 남은 원래 후보를 각각 한 번씩 추가 검사. 검사 통과 후보가 있으면 다음 판단에 사용 |
| ⑱ 비교 방법의 불필요한 의존성 | VLM 없이 PixelNav만 쓰는 비교 실행이 사용하지 않는 주변 관측 프로그램을 요구할 수 있음 | Direct-goal PixelNav는 VLM·주변 관측 프로그램을 실행하거나 요구하지 않게 구성. 공통 카메라·행동 변환·구동기는 공유 |
| ⑲ 속도값 전송의 반올림 | 소수 속도값을 통신 숫자로 바꾸면서 요청 상한을 아주 조금 넘으면 정상 명령이 거부될 수 있음 | 전송값이 요청 상한을 넘지 않게 표현. 구동 측 속도 제한은 그대로 검사 |
| ⑳ 장시간 실험의 기록·종료 | 전체 실험 시간과 목표 주입·기록·종료 도구의 상한이 다르면 도중에 끊길 수 있음 | 현재 전체 1800초 설정에 맞춰 목표 주입·종료·기록 상한 연결. 기록기 마지막 상한은 준비·종료 시간을 포함한 2040초. 정상 종료하면 기록도 함께 종료 |

**3. 현재 실행 설정**

**4. 현재 코드에 남은 문제 — 수정 완료로 표기하지 않을 것**

| 문제 | 현재 확인된 현상 | 아직 필요한 수정·확인 |

| 회전 정지 판정 | 요청 각도에 거의 도달해도 작은 반복 진동으로 완료하지 못하고 시간초과 가능 | 실제 정지·진동·미끄러짐을 구분하는 판정 보완 및 실기 확인 |
| 센서 처리 지연 | 명령 응답을 기다리는 동안 새 위치 자료를 처리하지 못해 ‘오래된 위치’로 종료하는 경로 재현 | 명령 통신 대기와 센서 처리 분리, 늦은 이동 명령의 재실행 방지까지 검증 |
| 목표 근처 복구 | 목표에 가까워졌다가 정지 반복 후 탈출 과정에서 다시 멀어지는 사례 | 움직인 거리와 최종 목표 접근을 구분하고 필요한 우회도 허용하는 복구 검증 |
| Direct의 정책 내부 제한 | 전체 시간과 별개로 300초 유효기간 및 기본 33번째 판단의 이력 제한 종료 존재 | 장거리 비교용 정책 기억·종료 조건 정합. 외부 500스텝 설정만으로 해결되지 않음 |
| 실제 영상·위치 정확도 | 카메라 header는 수신 시각. 위치는 로봇 자체 추정값 | 실제 촬영 시각, 카메라 보정 정확도, 물리 시작·도착 오차 확인 |
| 충돌 측정 | 물리 접촉을 자동으로 확인하는 입력 없음 | 현장 접촉 기록 사용. 프로그램의 충돌 미보고를 무충돌 증거로 사용하지 않음 |
