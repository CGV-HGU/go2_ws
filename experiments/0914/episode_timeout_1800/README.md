# 기록용 에피소드 제한 1800초 적용 — 2026-09-14

**Ours와 Direct-goal PixelNav의 다음 기록용 회차를 모두 1800초로 준비했다.**
주행·로봇 명령은 실행하지 않았다. 기존 17개 회차/준비 파일의 360초 조건과
지도·목표·모델·주행 속도는 유지하고, 새 준비 파일 10개를 만들었다.

## 어제 PixelNav 4번의 정성평가 사용 범위

`direct_goal-goal-4-002`는 사용자에게 개입·접촉·진로 방해가 없었다는 확인을
받았다. 약 35.40초에 모델 STOP으로 종료했고 추정 목표 잔여 거리는 7.46m다.
**‘가려진 최종 좌표를 직접 영상에 투영한 Direct-goal PixelNav가 목표 도달 전에
정지한 사례’**의 궤적·입력 영상·행동 분석에 쓸 수 있다.

5회 전체의 118개 선택 행동은 ESCAPE 기준 원본 및 저자 공식 코드에서도
재현됐다. 이는 같은 입력 조건에서 정책 추론의 행동 일치에 관한 근거다.
실로봇 baseline에는 look→20cm 전진과 카메라 변환이 포함되므로 ‘순정 정책
전체가 잘못됐다’고 기술하지 않는다. 마스크가 보이는 벽과 겹친 입력 조건,
추정 좌표라는 점을 표시한다. 나머지 회차의 미확인 현장 개입 여부를 임의로
‘없음’으로 채우지 않는다. [원본 대조·그림](../pixnav_direction_review/README.md).

정성 사례 선정과 정량 SR/SPL 집계는 구분한다. 기존 360초 결과를 1800초
성공/실패로 재표기하지 않으며, 같은 목표·설정·제한의 비교 집단을 명시한다.
유효한 최단 경로 길이가 없는 현재 자료에 Euclidean 거리를 대신 넣어 SPL을
계산하지 않는다. Ours의 성공한 회차만 골라 정량 비교하지 않는다.

## 바꾼 제한과 남긴 동작

| 경로 | 이전 | 새 1800초 회차 |
|---|---:|---:|
| 목표 발송부터 에피소드 제한 | 360초 | **1800초** |
| 목표 주입 스크립트가 허용하는 상한 | 900초 | 1800초 |
| 셸의 최종 종료 제한 | 420초 | 1860초 |
| 운영자 실행기의 전체 종료 제한 | 540초 | 1980초 |
| 몸체·영상·카메라 타이밍 기록 상한 | 600초 | 2040초 |

실제 기록기는 평상시 주행 종료와 STOP 처리에서 함께 종료된다. 2040초는
고정 대기 시간이 아니라 기록 누락을 피하기 위한 마지막 시간 상한이다.
이전 숫자 중 900/540/600초는 1800초 실행이나 후반 기록을 막는 경로였다.

준비기는 시간 제한을 manifest·목표 주입 인자·셸 제한·기록기에 함께 넣는다.
검증기는 이 값의 불일치를 거절한다. 운영자 실행기는 구형 준비 회차를 새
시간 조건에 재사용하지 않고, 기존 파일을 남겨 새 번호를 준비한다.

1800초는 사용자가 전달한 연구원의 시뮬레이터 전체 제한 설명에 맞춘 값이다.
시뮬레이터와 실로봇의 모든 종료 규칙이 동일하다는 뜻은 아니다.
다음 조건은 변경하지 않았다.

- 전진 0.5m/s, 일반 전진 25cm, look 요청 시 20cm 전진, 회전 0.8rad/s.
- 도착 반경 1m, 최종 yaw 미제어, 같은 표시 시작점에서 fixed-start odometry.
- Full 비동기 및 Direct의 VLM 없음/한 최종 목표 세션 조건.
- 정책 STOP, 정책 이력/step 한도, 각 회전의 실패·정지 조건, 데이터 freshness 검사.
- Ctrl+C·SIGHUP·외부 STOP과 종료 시 StopMove/서비스 종료·로그 보관 경로.

따라서 어제 Direct의 조기 STOP, Ours의 `MOTION_TIMEOUT`과
`LOCALIZED_POSE_STALE`은 전체 제한 증가로 해결됐다고 주장하지 않는다.

## 검증과 새 준비 파일

- 호스트 운영자·캠페인·시간 조건 검사: **59개 통과**.

  실제 ROS 메시지 타입에 가짜 I/O와 시계를 사용했다. 네트워크 none,
  ROS domain 214, 실제 ROS 노드 생성·명령 발행 없음.

  StopMove·서비스 해제·결과 기록을 실행했다. Direct 모델 STOP은 즉시 종료를 유지한다.
- 마지막 저장공간 계산을 포함한 시간 조건 검사: **17개 통과**.
  앞선 호스트 검사와 일부 중복되므로 이 숫자들을 합산하지 않는다.

## 저장공간: 장시간 연속 회차에 실제 제약이 있다

최근 Full 원본 기록의 전체 크기는 약 124초에 3.41GB, 302초에 7.31GB,
313초에 6.73GB였다. 센서 기록에는 준비·종료 구간도 포함되므로
에피소드 시간으로 나눈 값은 보수적인 대략치다. 주로 cloud/camera MCAP가 차지한다.
1800초로 단순 환산하면 약 40–50GB/회차가 될 수 있으며 압축률·장면에 따라 달라진다.

확인 시점 가용 공간은 약 **66.02GiB**다. 새 긴 회차는 관측된 기록량을 토대로
30MiB/s × 최대 시간 + 기존 10GiB 여유분을 확인한다. 1800초에서는
**62.73GiB**가 필요하며 현재 한 회차의 시작 조건은 통과한다.
여러 최대 길이 회차를 연속 저장할 공간은 아니다. 이후 공간이 부족하면
실험 원본을 외부 저장장치/서버로 옮기고 무결성을 확인한 뒤 정리해야 한다.
이번 변경에서 원본을 삭제하거나 옮기지 않았다. 예측치가 향후 최대 기록량을
보장하는 것은 아니다.

## 남은 우선 작업

1. **회전 종료 판정**: 목표각에 들어왔는데 잔여 진동 때문에 안정화 조건을
   통과하지 못한 사례를 해결해야 한다. 속도/시간만 일괄 증가시키는 것으로
   해결 완료 처리하지 않는다.
2. **제어기 pose 수신/처리 지연**: 독립 기록기는 신선한 pose를 받았는데
   제어기가 stale을 보고했다. 제어기가 보유한 타임스탬프와 콜백/명령 응답
   시간을 계측해 원인을 분리할 필요가 있다. RTAB-Map 지도 정합 실패로
   단정하지 않는다.
3. **네트워크와 VLM 대기**: 실제 Wi-Fi 단절과 HTTP timeout이 함께 있었다.
   USB 재삽입은 사용자 복구 조작이 포함된다. 원인과 복구 경로를 분리해서
   확인해야 하며, 현재 분석만으로 동글 고장이나 VLM 서버 결함을 확정하지 않는다.
4. **평가 조건 확정**: 가시 목표/가려진 목표의 Direct 입력 조건,
   개입/접촉/진로 방해·최단 경로·시작점 재배치 오차를 포함해 같은 조건으로
   기록한다. 현재 waypoint는 SLAM이 지속 보정하는 절대 Ground Truth가 아니다.

이번에 완료한 것은 시간 제한과 그에 필요한 기록/준비 경로 수정이다.
남은 항목이나 실제 장시간 주행 성공까지 검증 완료라고 보고하지 않는다.

## 보존 자료

기존 다른 소스 수정은 포함하지 않았다. `prepared-validation.json`에는 각
회차의 경로·해시와 기록기 조건 검사 결과가 있다. 모든 실행 로그와
`storage_samples.json`도 이 폴더에 보존한다. 커밋/푸시는 수행하지 않았다.
