# 실험 기록 용량·보존 범위 검토

2026-09-14 Jetson에서 실제 파일 크기와 기록 내용을 확인했다. **원본 삭제·이동, 주행 설정 변경, 기록 기능 비활성화는 하지 않았다.** 아래 용량은 GB(10억 바이트)이며 GiB와 구분한다.

## 결론

어제 Ours·Direct-goal PixelNav 에피소드를 핵심 자료로 보존하고, 이전 개발 시험의 대용량 생성 기록부터 정리할 수 있다. SR/SPL과 궤적 계산에 전체 고해상도 연속 RGB와 전체 점군은 필수가 아니다. 다만 **정책/VLM이 실제로 본 영상은 남겨야** 목표가 벽에 가려졌는지, 사람이 지나갔는지, 왜 잘못 회전하거나 STOP했는지를 다시 검토할 수 있다.

첫 정리 후보는 **실로봇 주행이 아닌 합성 부하 시험 bag 4개, 합계 18.174GB(16.925GiB)**다. 최근 실험 원본과 매핑 DB를 삭제하지 않고 확보할 수 있는 범위다. 아직 실제 삭제하지 않았다. 부하 시험 결과·실패 기록·스크립트는 보존해야 한다.

## 실제 용량

조사 시 파일시스템 가용 공간은 약 **70.89GB(66.02GiB)**였다. 세 실험 캠페인의 `episodes/` 아래 파일은 합계 **120.834GB**였다. 준비만 된 디렉터리도 포함한 디스크 사용량이며, 실행 횟수는 아니다.

| 세 캠페인의 에피소드 기록 종류 | 용량 | 의미 |
|---|---:|---|
| native 센서 bag | 113.350GB | 전체 RGB·점군·odom·IMU·보정 정보 |
| 별도 관측 프레임 | 6.457GB | 약 2fps PPM 이미지 |
| 정책 입력 | 0.352GB | 실제 정책 입력 NPZ·단계 JSON |
| 정책/VLM trace | 0.102GB | 요청 영상·응답·정책/비동기 이벤트 포함 |
| 본체 상태 | 0.230GB | IMU·Sport·관절 상태 |
| 실행 이벤트 | 0.212GB | 시각·pose·목표·명령·상태·종료 |

나머지는 카메라 시각, 배포 설정, 텍스트 로그 등이다. **두 종류의 연속 영상/센서 기록이 대다수 용량을 사용한다.** 회차별 내역은 [episode_storage.csv](episode_storage.csv)에 있다.

Ours 4번 성공 회차 `recording-five-goals-20260913/full-goal-4-009`는 총 7.308GB였다. native bag 6.834GB, 별도 관측 이미지 0.402GB, 정책 입력 0.026GB다. 이 회차의 537.825MB bag 한 조각을 실제로 읽으면 압축 전 메시지 바이트의 **RGB 89.11%, 점군 10.56%**였다. 압축 후 파일 용량을 토픽별로 정확하게 분배한 수치는 아니다. [측정 원문](bag_sample_topic_bytes.log)

## 앞으로 남길 최소 기록

| 자료 | 보존 목적 |
|---|---|
| 시간 포함 XY/yaw, 원시 odom, 제어에 사용한 pose, 시작/목표 좌표와 좌표계 | 궤적·거리·종료 시점 재계산, 좌표 오류 구분 |
| 실제 명령·결과·상태·중단 사유, IMU/Sport | 회전 지연·꿀렁거림·수신 지연 원인 분석 |
| 정책의 실제 입력 이미지/goal mask, raw/effective 출력, STOP 출처 | PixelNav 행동 재생과 목표 입력 검증 |
| VLM 요청 영상·응답·시각·지연·실패, 비동기 결정/큐 이벤트 | Full 비동기 동작과 네트워크 대기 검증 |
| 지도/보정값/모델·코드·설정 해시, 성공 반경·시간제한 | 실험 조건 재현 및 공정한 비교 |
| 개입·접촉·진로 방해·현장 도착 확인 | 자율 성공 여부와 수동 이동 구간 구분 |
| 결과 JSON, 궤적 CSV, 원본 목록·해시, 기록 완전성 결과 | 분석·공유·누락 추적 |

지도 DB는 매 회차 대용량 복사 대신 불변 원본 하나와 그 해시를 참조할 수 있다. SPL에는 같은 지도/시작/목표에 연결된 검토된 장애물 고려 최단 경로 기준도 필요하다. 전체 연속 영상 없이도 이 기준을 보존할 수 있다.

**매 주행에서 생략 가능한 후보**는 고해상도 연속 RGB, 전체 점군, 중복 PPM 관측 이미지다. 정책 입력과 VLM 요청 안의 실제 영상은 유지한다. 정책 영상만으로 관측 사이의 접촉까지 모두 입증할 수는 없으므로, 정성 영상이 필요하면 낮은 용량의 연속 영상은 선택 사항으로 두고 현장 기록을 함께 남긴다. 매핑/정합/보정/센서 오류를 다시 조사할 전용 회차에는 전체 RGB·점군 기록을 유지한다.

기존 Ours 두 세트와 PixelNav를 핵심으로 보존하는 방향은 합리적이다. 다만 결과 목록에서 세 캠페인의 목표 발송 기록은 24건이고, 실제 PixelNav 5회는 모두 4번 목표다. 5번은 재촬영하면서 좌표가 바뀌었다. 현재 자료를 모든 골의 동일 조건 두 세트라고 자동 묶거나, 성공만 골라 나머지를 없애지는 않는다. 에피소드별 성공·실패·개입·설정 변경 이력은 작은 용량이므로 모두 보존한다.

## 축소 가능성 확인과 현재 적용 상태

위 Ours 4번 원본 bag 한 조각에서 RGB·점군을 제외하고 odom·IMU·camera info·static TF만 **새 파일로** 추출했다. 537.825MB가 **0.778MB**가 됐다. 보존한 odom 2,721개, IMU 4,104개, camera info 337개, static TF 1개의 **메시지 시각·내용·개수가 원본과 정확히 일치**함을 스트림 해시로 검사했다. 원본은 읽기 전용으로 유지했다. [검증 결과](compact_sample_result.json)

이는 **센서 bag 한 조각의 축소 실증**이다. 전체 에피소드가 같은 비율로 작아진다거나, 현재 실시간 기록 설정을 경량 방식으로 검증했다는 뜻은 아니다. 위의 정책 입력/pose/명령/현장 기록 등은 이 작은 bag 밖에서 별도로 보존해야 한다.

현재 `robot_recording_integrity.py`의 시작 검사와 종료 검사는 RGB·점군·별도 관측 프레임을 필수로 요구한다. 따라서 후속 경량 기록 적용에는 준비기·기록기·검사기·manifest를 함께 수정해야 한다. 단순히 RGB/점군 파일을 없애거나 토픽만 끄면 출발 전 오류 또는 기록 누락이 발생한다. 과거 파일을 축소할 때도 원래 기록 검사 결과와 원본 해시는 그대로 보존하고, 삭제한 항목/보존 항목/파생물 해시를 별도 retention manifest에 남겨야 한다.

앞선 작업에서 Ours/Direct의 다음 회차 전체 제한과 기록기 상한은 1800초에 맞춰 수정했다. 이번 저장공간 조사에서는 그 설정을 추가 변경하지 않았다. **현재 실행 스크립트는 여전히 전체 센서 기록 방식**이며, 경량 기록 방식으로 이미 바뀐 것으로 이해하면 안 된다.

## 측정 재현

- `audit_storage.py`: `.local-data`를 파일 메타데이터로 조사. 원본 수정·삭제 기능 없음. 현재 파일 크기는 이후 기록에 따라 바뀔 수 있다.
- `compact_bag_sample.py`: `rosbag2_py`로 한 조각을 읽고 보존 대상 스트림만 새 bag에 기록. `rclpy`를 초기화하거나 ROS 발행을 하지 않는다.
- 실험 컨테이너: `sha256:478e26f81e6d344e691215508b9409939df53ed46bf57f5bcfd1d04356ca0d28`; `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 1000:1000`. 원본 MCAP은 `/input/sample.mcap:ro`, 이 보고서 폴더만 `/out`으로 쓰기 허용했다. `/opt/ros/jazzy/setup.bash`를 읽고 `/out/compact_bag_sample.py`만 실행했다. 소요 약 3.18초, 물리 명령 0건.
- `storage_inventory.json`, `episode_storage.csv`, `cleanup_candidates.json`은 조사 스크립트 출력이다. 샘플 bag 재생성은 별도 빈 출력 위치에서 수행해야 하며 기존 샘플을 덮어쓰지 않는다.

이번 묶음과 최상위 안내만 추가했다. 원본 실험·기존 분석 묶음·매핑 DB·로봇 제어 설정은 변경하지 않았고 커밋/푸시는 하지 않았다.
