# 2026-09-13 Jetson 주행 로그 검토와 ESCAPE–Direct PixelNav 비교 준비

이번 검토는 본체를 끈 상태에서 수행했다. 주행 명령을 발송하지 않았다. **다음 실험은 저장된 목표 2번·1번의 ESCAPE Full 주행을 먼저 수행하고, 같은 목표로 Direct PixelNav 한 세트를 비교한다.** 새 5m 직선 시험을 별도 선행 조건으로 추가하지 않는다.

## 수정한 관측 전환 결함

긴 주행의 마지막에는 새 GO가 승인됐지만 아직 첫 PixelNav 동작 결과가 없는 순간에 관측 정지 요청이 들어왔다. 기존 코드는 이때 이전 동작 결과가 있다고 가정하고 GO를 닫다가 assertion에서 실패했다. 정지 요청 표시는 이미 지워져 관측 관리자가 기다리던 정지 확인이 전달되지 않았고, 결국 약 90.17초 후 취소됐다.

첫 동작 전에도 새 영상이 도착하면 동작 수 0인 정상 관측 체크포인트를 반환하도록 수정했다. 이미 실행 중인 명령의 완료·정지 확인과 영상 신선도 조건은 유지한다. 실제 VLM 결과 처리 경로와 DDS 통신에서 정지 확인, 보정된 GO 보류, 관측 복귀 후 첫 보정 동작 전달까지 검증했다. 이 시험은 수정 후 실로봇의 전체 목표 도착을 재현한 것이 아니다.

기존 이미지에서는 해당 경계 조건 15개가 동일 assertion으로 실패했고, 수정 이미지에서는 통과했다. 테스트가 설치된 코드를 사용하도록 먼저 import한 뒤 검증했다. 초기 시도 중 소스 디렉터리를 잘못 import해 통과한 로그는 원본 결함 검증 근거에서 제외했다.

## 룩 처리와 걷다 서다 하는 이유

현재 `look_up`/`look_down`은 정책에서 삭제하거나 성공했다고 속여 넘기지 않고, 실행 단계에서 **10cm 전진**으로 대체한다. 새 실제 영상과 이동 후 목표 상대 좌표로 다음 정책 추론을 진행한다. 몸체 pitch, 가상 crop/확대, 시선 원근 변환은 이번 조건에 사용하지 않는다. 따라서 이것은 물리적인 위·아래 관측 구현이 아니라 두 방법에 공통 적용하는 로봇 실행 방식이다.

저장된 실제 체크포인트·입력 영상으로 6개 주행의 41개 정책 세션, 154스텝을 다시 추론했다. 액션과 정책 입력이 일치했고 logits도 허용 오차 1e-5 내에서 일치했다. 액션은 look_down 78, 전진 57, 우회전 10, 좌회전 3, STOP 6이었다. **실제 look_up 표본은 0개**이므로 이번 재생으로 look_up 실주행까지 검증했다고 하지 않는다.

명령 완료 로그상 10cm 78회 중 76회 OK, 2회는 목표 도착에 따른 정지로 중단됐다. 일반 25cm도 57회 중 55회 OK, 2회 도착 정지였다. 10cm 동작 시간 중앙값은 약 0.98초, 25cm는 1.42초다. 이 자료는 10cm 실행의 근거이며, 5cm·20cm보다 최적이라는 비교 결과는 아니다.

각 전진 매크로마다 감속·정착을 확인하므로 걸음 사이 정지가 생긴다. VLM 비동기 계산이 동작 중 겹쳐 진행되더라도 연속 속도 주행과 같지는 않다. 마지막 긴 회차의 VLM navigation 호출 20개는 중앙값 2.83초, 최대 3.05초였다. 마지막 긴 대기를 네트워크 단절 탓으로 돌릴 근거는 없었다. 초기 전체 관측은 전진 시작까지 수십 초를 차지하므로 주행 시간 분석에 따로 남긴다.

회전 92회는 90회 OK, 1회 타임아웃, 1회 목표 도착 정지였다. 정지 후 몸체가 되돌아오고 재보정하는 패턴이 관찰된다. 회전 중앙값 5.89초이며 일부 30도 회전도 약 14초 걸렸다. 이번에는 회전 제어를 임의로 더 완화하지 않았다. 이 잔여 문제는 다음 실주행에서 자세·발 움직임과 함께 확인해야 한다.

## 고정 시작점과 로컬라이제이션

7개 회차의 저장 좌표→출발 시 오도메트리 목표 변환을 다시 계산했고 수치 오차는 0이었다. 발행된 PointGoal과 가까운 이전 오도메트리 표본을 비교하면 거리 오차 p95는 모든 회차에서 1cm 이내였다. 이는 좌표 변환·메시지 일관성 검증이며 실제 위치 정확도 검증은 아니다.

현재 성공한 짧은 목표 방식은 **표시된 같은 위치·방향에서 매번 원점을 다시 잡는 오도메트리 주행**이다. ICP 보정을 사용하지 않는다. 정지 상태에서도 RTAB-Map 방향이 15~20도 이상 변한 자료가 있어, 이를 정상 전역 로컬라이제이션이라고 판단하지 않는다. 이번 비교를 위해 광범위한 ICP 재조정이나 재매핑을 먼저 요구하지 않는다.

출발 방향 오차는 목표 위치를 함께 회전시킨다. 12.526m 목표에서 5도 오차는 약 1.09m에 해당한다. 두 방식 모두 같은 표시와 방향으로 재정렬해야 하며, 다른 장소에서 임의로 재시작할 수 있는 방식으로 설명하면 안 된다.

## Direct PixelNav 비교 준비

기존 Direct 실행에도 Full 관측 관리자가 시작되고 준비 조건에 포함돼 있었다. VLM이 없는 Direct에서 관측 대기가 발생할 수 있으므로, **Direct 모드에서는 VLM과 Full 관측 관리자를 실행하거나 요구하지 않도록 수정**했다. Full은 기존 비동기 기능을 유지한다.

Direct는 하나의 최종 목표를 PixelNav에 직접 유지한다. Full의 중간 목표별 50스텝 상한을 Direct 전체 에피소드에 적용하면 조기 종료되므로, Direct 최종 목표 세션 상한은 명시적으로 500스텝으로 정했다. 이는 임의의 성능 최적화 수치가 아니라 전체 시간 제한 내 조기 절단을 피하기 위한 상한이다. **두 방식의 전체 에피소드 제한은 동일하게 360초**다. Direct 정책 STOP 후 Full/VLM으로 넘겨 재시도하지 않는다.

| 공통 조건 | 값 |
|---|---|
| 시작점·목표 | 같은 표시된 시작점과 기존 목표 1·2번, 동일 goal-plan 해시 |
| 순서 | ESCAPE 2 → ESCAPE 1 → Direct 2 → Direct 1 |
| 도착 | 자동 거리 1m, 최종 yaw 미요청 |
| 입력·실행 | 동일 체크포인트, calibrated_4_3 카메라, 10cm 룩 대체, 25cm 일반 전진, 같은 회전 제어 |
| 종료 | 같은 360초 제한; 개입·실패·재시도를 모두 별도 회차로 보관 |
| 기록 | 궤적, 거리, 시간, 종료 이유, 액션/ACK, 정책 입력, VLM 호출·모델, 원본 센서, 현장 보고 |

최소 한 세트는 두 목표 × 두 방식 = 네 회차다. 기존 6회 Full은 수정 전 예비 실험으로 보관하며, 새 Direct와 조건이 같은 새 비교 세트에 섞지 않는다. 표본이 두 목표뿐이면 제한된 정량 비교로 보고하고 일반 성능 입증으로 확대하지 않는다. 후속 반복에서는 방법 순서 효과도 줄여야 한다. VLM 서버 모델이 바뀌면 이름·서빙 버전을 기록해 조건 변경을 구분한다.

## 원본 기록 누락 보완

짧은 6회 모두 주행 중 점군 원본이 없었다. 일부 bag에 점군이 있어도 주행 전후의 mapping 토픽만 들어 있었다. Full이 센서 입력을 인수하면서 mapping 입력이 멈췄기 때문이다. RGB·오도메트리·IMU와 정책 재생 자료는 남아 있다. 없는 주행 중 점군을 복원했다고 주장하지 않는다.

매핑 세션 기록에 `/s2e/robot/sensors/cloud`를 추가했다. 새 Full/Direct 준비 파일에도 같은 원본 기록 서비스를 포함했다. 명령 서비스 시작 때 함께 기록하고, 명령 종료 후 SIGINT로 bag을 마무리한다. 이는 읽기 전용 기록이며 별도 SLAM이나 센서 발행자를 시작하지 않는다.

네트워크가 격리된 실제 MCAP 기록기에서 mapping 점군 40개 후 navigation 점군 60개로 발행자가 바뀌는 상황을 시험했다. 두 토픽 모두 보존됐고 RGB/odom/IMU 각 100개와 정상 종료를 확인했다. 실제 주행 후에는 시간 구간별 수신 수를 다시 확인해야 한다. bag 파일이 존재한다는 사실만으로 자료 완전성을 판정하지 않는다.

## 정량 지표의 사용 범위

검토 중 별도 커밋 `387ea6a`에 정리된 SR 83.3%, SPL 75.1%를 확인했다. 숫자 자체는 기존 도착 상태와 직선 기준 거리를 사용하는 계산과 부합한다. 그러나 다음 제한이 있다.

- SR 83.3%는 오도메트리 기반 자동 도착률이다. 실제 목표까지 거리를 측정한 성공률과 구분한다.
- SPL 75.1%의 기준 길이는 검증된 통행 가능 최단경로가 아니라 저장 좌표의 직선거리다. 현재는 **직선거리 기준 대리 지표**로 표기한다.
- 2번의 계산값 100%는 1m 반경에서 일찍 멈춰 누적 길이가 시작–목표 거리보다 작으면 공식의 분모가 기준 길이로 제한되는 영향도 있다. 경로가 정확한 직선이었다는 증거가 아니다.
- 모든 개입·접촉 항목을 확인하지 않은 회차까지 ‘전 회차 0건’으로 바꾸지 않는다.

SPL은 최단 통행 경로와 실제 이동 경로, 사전에 정한 성공 조건에 기반한다. 원 논문은 에이전트의 DONE과 지오데식 거리를 권고한다. 이번 사용자 지정 조건은 자동 1m 도착 종료이므로 그 차이를 명시한다. [Anderson et al., On Evaluation of Embodied Navigation Agents](https://arxiv.org/abs/1807.06757)

후속 현장에서는 실제 목표 표식을 기준으로 종료 거리와 측정 방법을 남긴다. 시작–목표 직선 통행이 가능한지 확인하거나 검토된 지도/실측 최단경로를 확보한다. 기준 경로가 미확인일 때 공식 SPL 칸은 비워 두고 궤적과 대리 지표를 보관한다. 원래 지표 파일은 덮어쓰지 않고 이 검토를 별도로 첨부했다.
